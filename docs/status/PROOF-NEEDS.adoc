= Spline proof obligations

These obligations describe the actual alignment boundary, replacing template
ABI/FFI obligations for components that Spline does not implement.

[cols="1,3,3",options="header"]
|===
| Obligation | Required statement | Evidence needed
| Alignment | Every registered variant maps to the intended consumer schema and encoding | Versioned mapping, authoritative checker and deliberately invalid examples
| Codec correspondence | Decode(encode(x)) preserves the declared message semantics over the supported domain | Consumer codec properties, malformed/truncated/unknown-variant cases; golden samples alone are insufficient
| Posture blindness | Equivalent payloads have the same wire representation independently of local posture/rank | Schema review and controlled cross-posture captures, not only a string search
| Token boundary | The wire token is opaque; each endpoint enforces authority, expiry and consumption | Live pairing with valid, forged, expired and reused tokens, and cleanup observations
| Plane independence | Control and media retain their declared ordering/loss properties | Consumer transport integration and fault-injection evidence
|===

No machine-checked universal Spline theorem or proof-to-binary connection is
claimed. Cleave and Groove have separate, scoped Idris models; those do not
establish these cross-repository wire properties automatically.
